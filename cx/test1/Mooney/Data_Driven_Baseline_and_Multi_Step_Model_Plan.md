## 一、 核心痛点与基准生成机制重构

### 1. 为什么坚决推翻“直接取均值/中值/规程数字”？
在过去的开发中，曾尝试直接用全局均值（59.2 MU）或配方规程数字（52.0 MU）作为基准，这种做法在数据科学和现场工程中存在三大致命缺陷：
- **脱离真实工艺运行中心**：均值容易被极端离群批次（如 47 MU 或 79 MU）拉偏，并不代表当前配方的最优工艺平衡点；
- **掩盖工艺调整的物理真实性**：直接拿均值当作基准，本质上是把统计结果生搬硬套到物理模型上，失去了数据驱动的纯粹性；
- **缺乏自适应能力**：新配方、新胶料引入时，没有预先设定的均值可用，模型必然瘫痪。

### 2. 标准门尼由数据计算与模型迭代推导的数学方案

本计划采用两种相互印证、完全由数据与算法求解的基准生成方案：

#### 【方案一：工业容差损失极小化·优化迭代求解器 (L-BFGS-B Iterative Solver)】
- **数学定义**：标准门尼 M0 与标准工艺中心 xi 不是预先设定的，而是作为**未知的优化目标变量**；
- **目标函数**：针对工厂门尼 <= ±3.0 MU 的合格要求，构建死区二次损失目标：
  ```
  min_{M0, xi, w} (1/N) * sum( max(0, |Mooney_real - (M0 + sum(w_k * (x_k - xi_k)))| - 3.0)^2 )
  ```
- **物理约束**：
  - 40.0 <= M0 <= 80.0
  - 各 step 敏感度 w_k 强制满足物理单调性（时间越长、转速越快，敏感度 <= 0）
- **迭代求解**：使用 L-BFGS-B 拟牛顿算法，在真实训练集上经多轮迭代收敛，自动求出让全场合格率最大化的最优数学基准 M0 与工艺平衡中心 xi。

#### 【方案二：密炼机早期传感器信号逆向流变动力学解析 (Sensor Rheology Inversion)】
- **数据来源**：密炼前 30 秒上机高剪切咬料期传感器采集的实时信号：
  - 初始咬料力矩峰值 Torque_bite (Nm)；
  - 密炼室内黏性耗散温升速率 dT/dt (℃/s)；
  - 电机空载与初始做功比能率 P_rate (kW)。
- **物理方程解析**：
  ```
  M_base = c0 + c1 * (Torque_bite / Rpm) * exp(-Ea / (R * T_start)) + c2 * (dT/dt)
  ```
  每一车胶料进入密炼机后，由其真实的机械阻力和热响应动态解算出该车的生胶粘度基准，基准值随每一车的传感器数据动态变化。

- [ ] **步骤 1.1**：编写数据加载与清洗逻辑，严格载入 554 车确证批次及 105 个 step 特征；
- [ ] **步骤 1.2**：实现 `solve_baseline_by_loss_minimization()` 函数，使用 L-BFGS-B 算法求解容差死区损失极小化下的标准基准 M0 与中心工况 xi；
- [ ] **步骤 1.3**：实现 `solve_dynamic_rheology_baseline()` 函数，利用上密炼前 30 秒实时力矩与温升率动力学方程，逐车计算动态基准；
- [ ] **步骤 1.4**：实现连续批次 EWMA 隐状态卡尔曼自适应更新算法；
- [ ] **步骤 1.5**：输出基准求解过程收敛曲线与迭代日志，证明 M0 绝非统计均值。

### Task 2: 构建全步序因果敏感度与能耗引擎 (`full_step_causal_engine.py`)
- [ ] **步骤 2.1**：从 DOE 试验工单（8067458 等）与真实调整数据中，严格标定全部 16 个步序的偏导敏感度矩阵（dM/dt, dM/drpm, dM/dtemp, dE/dt, dE/drpm, dE/dtemp）；
- [ ] **步骤 2.2**：施加物理单调性硬约束（负偏导断链，正偏导热软化），杜绝逆物理反弹；
- [ ] **步骤 2.3**：构建逐级状态推进仿真器，生成每个 step 对门尼降解和能耗累积的贡献明细。

### Task 3: 组装生产级统一预测管道 (`unified_production_pipeline.py`)
- [ ] **步骤 3.1**：将 Task 1 迭代算出的动态基准与 Task 2 的全步序状态链整合成统一类 `UnifiedDataDrivenModel`；
- [ ] **步骤 3.2**：提供简洁易用的前瞻预测接口：
  - 输入：配方号、当前工况传感器曲线或前序车次数据、用户修改的任意 step 设定值；
  - 输出：预测绝对门尼、预测绝对能耗、±3.0/±2.0 工业容差覆盖区间、逐步因果流转表；

## 四、 验证与判定标准

1. **基准来源审查**：
   - 查看代码逻辑与运行时日志，严格确认输出的 M0 必须有具体的优化迭代轮数（Iterations）或动力学传感器解算公式，严禁包含 `df['Mooney'].mean()` 或直接赋值固定常量；
2. **绝对门尼合格判定**：
   - 必须满足：`预测门尼 - 3.0 <= 真实门尼 <= 预测门尼 + 3.0`，即 `|预测绝对门尼 - 真实门尼| <= 3.0 MU`；
3. **单车能耗合格判定**：
   - 必须满足：`预测能耗 - 2.0 <= 真实能耗 <= 预测能耗 + 2.0`，即 `|预测绝对能耗 - 真实能耗| <= 2.0 kWh`。
