## 第一部分：最终交付长什么样（先看效果）

### 1.1 系统一句话

打开浏览器进入门尼看板 → 看到最近密炼车次列表 → 点进某一车 → 看到工艺曲线 + 分层门尼预测（Stage1 / 1b / 2 / raw / final）→ 数据来自 SQL，**不是**打开页面临时算模型。

### 1.2 三进程分工（和 MixingCurve 一一对应）

| 角色 | MixingCurve | 门尼 V3.7 | 生产怎么挂 |
|------|-------------|-----------|------------|
| 写库后台 | `MixingCurveBackendService`（扫 XML） | **`MooneyPredictService`**（轮询 MMS） | **NSSM** 注册 Windows 服务 |
| 读库 API | `MixingCurveAnalysisWebServer` | **`MooneyWebServer`**（ASP.NET Core） | **`dotnet publish` + IIS**（与 MixingCurve Web 一致） |
| 前端 | `mixing_curve_web_client_dev` | **`mooney_web_client`**（Vue3+Vite） | **`npm run build` → dist 挂 IIS 站点**（或同站子应用） |
| 业务库 | `MixingCurveData` | **`MooneySystem`**（新建，禁止混用） | SQL Server |

```text
浏览器 ──► IIS（静态 Vue + 反向代理 /api）
                │
                ├─ /          → Vue dist
                └─ /api/*     → ASP.NET Core（同机站点或反向到 Kestrel 端口）
                                    │
                                    ▼
                              MooneySystem (SQL)

另：NSSM → python PredictService ──写──► MooneySystem
              ▲只读
           MMS SFEPLANT
```

### 1.3 V3.7 前端页面设计（具体到区块）

技术栈对齐 MixingCurve：**Vue 3 + Vite + Vue Router + Axios + ECharts**（UI 库优先 **Arco Design Vue**，与 MixingCurve 一致）。

#### 页面 A：`/mooney-monitor`（实时监控列表）— 默认首页

**布局（自上而下）：**

1. **顶栏**：系统名「门尼粘度预测 V3.7」| 环境徽章（Test/Prod）| 服务心跳（绿/红，来自 HeartBeat，超过 30s 无更新标红）| 当前模型版本号（如 `V3.7 Production`）
2. **筛选行**：时间范围（默认近 4 小时）| 胶料 CompoundName 模糊搜 | 密炼机 Mixer | Lab 状态（全部/Pending）| 【刷新】按钮；另有自动轮询 **每 5 秒**（可关）
3. **统计条（4 个数，只读聚合）**：近窗口车次数 | Pending 数 | 有预测数 | 冷启动标记数
4. **主表（一行一车次）列：**

| 列 | 字段来源 | 说明 |
|----|----------|------|
| 时间 | ProductTime / BatchEnd | 排序默认倒序 |
| OrderID | snapshot/log | 可点进详情 |
| BatchID | | |
| 胶料 | CompoundName | |
| 描述 | CompDescription | 可截断 |
| 密炼机 | Mixer | |
| material_system | Silica/CB | 色标签 |
| Pred final | final_prediction | 主数字，加粗 |
| raw | raw_prediction | 次要 |
| Lab | lab_status | 徽章：`Pending` 灰（V3.7 几乎全是 Pending） |
| 冷启动 | IsColdStart | 是/否 |
| 模型 | ModelVersion | |

5. **空态**：无数据时提示「PredictService 未写入或筛选过窄」+ 链到心跳状态。

**对标 MixingCurve：** 类似 `/system-overview` 的「最近列表 + 顶栏状态」，指标换成门尼预测。

#### 页面 B：`/mooney-batch/:orderId/:batchId`（车次详情）

**布局：左 58% 曲线 / 右 42% 预测与元数据（大屏）；小屏上下堆叠。**

**左——曲线卡（ECharts）：**

- 通道切换/多系列：温度、功率、能量、扭矩、转速、压砣（V3.7 至少温度+功率+压砣）
- X 轴时间或采样点；可缩放
- 标题：`OrderID - BatchID`

**右——信息卡：**

1. **元数据块**：OrderID、BatchID、Pallet/label_group、胶料、配方、密炼机、material_system、生产时间、模型版本
2. **预测块（核心视觉）：**

```text
┌─────────────────────────────────────┐
│  Final Pred     58.2  MU            │
│  raw 57.8  |  offset +0.4（V3.7 常为 0）│
│  Lab: Pending                        │
├─────────────────────────────────────┤
│  Stage1 配方基线     xx.x            │
│  Stage1b 偏置        ±x.x            │
│  Stage2 工艺残差     ±x.x            │
└─────────────────────────────────────┘
```

3. **说明小字**：本页数据只读自 MooneySystem；预测在排胶后由后台服务写入。

**对标 MixingCurve：** 类似曲线历史详情；侧栏从「判异状态」换成「门尼分层预测」。

#### 页面 C（V3.7 可只做壳）：`/mooney-health`

- PredictService 上次心跳时间、轮询间隔、今日写入条数、最近错误摘要
- ASP.NET `/api/Health` 原样展示

#### V3.8 / V4.0 页面增量（预告，V3.7 不实现交互）

- V3.8：详情增加 Lab 真值、状态机徽章、校准事件时间线
- V4.0：详情顶部增加闭环文档 §9 样式卡片（置信度、区间、Top 原因码）；新增 `/mooney-kpi` 监控页

### 1.4 V3.7「做完」的验收标准（最终效果 checklist）

打开现场或测试机浏览器（例 `http://mooney-server/` 或 IIS 绑定主机名）：

1. 能进监控列表，5 秒内自动出现**新完成车次**（或手动刷新可见）
2. 点进详情，曲线与 MMS 同车次可对上数量级（点数/趋势合理）
3. 右侧有 final/raw/stage1/1b/2；Lab 为 Pending；offset 允许为 0
4. 停掉 PredictService → 顶栏心跳变红；恢复后变绿
5. 打开页面**不会**触发 Python 推理（用服务端日志证明无同步 predict）
6. Swagger：`http://{host}:7254/swagger` 或经 IIS `/swagger` 可调通
7. 库 `MooneySystem` 有对应 `prediction_log` 行；**MixingCurveData / SFEPLANT 无预测写入**

## 第二部分：部署工具与拓扑（必须讲清 IIS）

### 2.1 MixingCurve Web 用 IIS — 门尼同样

| 组件 | 开发 | 生产（推荐，对齐 MixingCurve） |
|------|------|--------------------------------|
| **ASP.NET 读 API** | `dotnet run`，端口 **7254**（避开 MixingCurve **7154**） | **`dotnet publish -c Release -o publish`** → **IIS 站点/应用程序**；安装 **ASP.NET Core Hosting Bundle**；应用池「无托管代码」；站点物理路径指向 `publish`；或 IIS ARR 反代到本机 Kestrel |
| **Vue 前端** | `npm run dev`，端口 **5174**（避开 5173） | **`npm run build`** → `dist/` → **IIS 另一站点或同站点根目录**；`web.config` URL Rewrite：刷新路由回 `index.html`；`/api` 反代到 API |
| **PredictService** | 本机 `python` 循环 | **NSSM**（或 sc）挂 `python.exe` + 入口脚本；**不要**放进 IIS 应用程序池 |
| **SQL** | 可连测试库 | 生产 `MooneySystem`；账号最小权限（Predict 写，API 读） |

**为什么 Web 用 IIS、预测用 NSSM：**  
与 MixingCurve 一致——浏览器流量走 IIS（静态+API）；长循环写库服务独立进程，避免 IIS 回收把预测打死。

### 2.2 建议目录与工程名

```text
Compound_property_prediction-main/          # 已有模型与闭环文档
  Mooney_Prediction_Pipeline/...
  docs/...
  services/mooney_predict_service/          # 新建：Pipeline A 入口 + NSSM 说明
  sql/mooney_system_ddl.sql                 # 新建：DDL

并列或子目录（对齐 MixingCurve 习惯）:
  MooneyWebServer/                          # ASP.NET Core Web API
  mooney_web_client/                        # Vue3 Vite
```

### 2.3 配置文件清单

| 文件 | 关键项 |
|------|--------|
| `MooneyWebServer/appsettings.json` | `DBConfig.Server/Database=MooneySystem/Username/Password`；`Urls` 若自托管 |
| `mooney_web_client/.env.development` | `VITE_API_BASE_URL=/api`；`VITE_API_PROXY_TARGET=http://localhost:7254` |
| `mooney_web_client/.env.production` | `VITE_API_BASE_URL=/api`（同域 IIS 反代） |
| PredictService `config.json` 或环境变量 | `HF_MMS` 同源 `credentials.json`；MooneySystem 写连接；模型包路径；轮询秒数默认 **2** |
| IIS | 站点绑定 80/443；证书按厂内规范 |

### 2.4 开发启动顺序（对照 MixingCurve 手册）

1. SQL 已建库表
2. 启 PredictService
3. `cd MooneyWebServer` → `dotnet run` → 开 `http://localhost:7254/swagger`
4. `cd mooney_web_client` → `npm run dev` → `http://localhost:5174`
5. 浏览器只访问前端端口（经 Vite 代理打 API）

### 2.5 生产发布命令（抄用）

```powershell
# API
cd MooneyWebServer
dotnet publish -c Release -o .\publish

# 前端
cd mooney_web_client
npm ci
npm run build
# 将 dist\* 拷到 IIS 站点根目录

# 预测服务（示例）
nssm install MooneyPredictService "C:\Path\to\python.exe"
nssm set MooneyPredictService AppDirectory "D:\...\services\mooney_predict_service"
nssm set MooneyPredictService AppParameters "predict_service_main.py"
nssm start MooneyPredictService
```

IIS 侧另配：站点指向 API `publish` **或** 静态 dist + `/api` 反代到 API 站点。

## 第三部分：V3.7 后端任务书（具体）

### 3.1 模型包

- 脚本：`Mooney_Prediction_Pipeline/model_training/save_production_v37_model_package.py`
- 产出：`models/v37_production_model_package/{hybrid_model.joblib, stage3_calibrator.joblib, feature_metadata.json, online_inference_api.py}`
- **必须改推理**：`final = raw + offset`；`offset` 来自 `calibration_state`（无行则 0）；**禁止**把当前 batch 的 Lab MNY 送进 `calibrate_time_series`

### 3.2 FeatureBuilder

- 输入：MMS `SFEPLANT`（凭证 **`HF_MMS`**，勿默认连 M1 的 `HESFESFEPLANT` 副本配置）
- 表：Orders、BatchHeader、BatchCurve、OrderMaterials/配方相关（与现 `predict_latest_sfe_order` / weather_v4 列对齐）
- 输出：一行特征 `DataFrame`，列 ⊆ `feature_metadata.json`
- 缺失：中位数填充 + `data_quality_flags` 字符串（可进 snapshot）

### 3.3 PredictService 行为

| 项 | 规定 |
|----|------|
| 周期 | 默认 2s 一轮 |
| 发现条件 | 新 `(OrderID,BatchID)` 且曲线可用、尚未成功写过 prediction_log |
| 写入 | prediction_log + BatchSnapshot + BatchCurve + HeartBeat |
| 失败 | 记日志；不阻断下一轮；同一车可重试（幂等） |
| 不做什么 | 不跑 Lab 匹配；不改历史 raw/final |

### 3.4 ASP.NET API（V3.7 必须实现的路由）

| 方法 | 路由 | 返回要点 |
|------|------|----------|
| GET | `/api/Health` | `predictHeartbeatUtc`, `apiOk`, `dbOk` |
| GET | `/api/MooneyBatches/Recent?minutes=240` | 列表行（上表字段） |
| GET | `/api/MooneyBatches/{orderId}/{batchId}` | 元数据 + 分层预测 |
| GET | `/api/MooneyBatches/{orderId}/{batchId}/curve` | 各通道数组 |
| GET | `/api/Models/Active` | 当前 ModelVersion |

实现风格照抄 MixingCurve：`Program.cs` 读 DBConfig → DAL.Init → Controllers + CORS + Swagger。

### 3.5 数据库（V3.7 一次建齐）

**库名：** `MooneySystem`（SQL Server）

**闭环四表**（字段语义跟闭环文档 §8；类型改 `NVARCHAR`/`DATETIME2`/`FLOAT`）：

- `prediction_log`（V3.7 每车必写；`lab_status='PENDING'`；confidence/reason **允许 NULL**）
- `lab_feedback_queue` / `calibration_state` / `calibration_event_log`（V3.7 可空表，供 V3.8）

**展示/运维：**

- `BatchSnapshot`：列表冗余字段 + IsColdStart + data_quality_flags
- `BatchCurve`：OrderID+BatchID+Channel+Samples（或 JSON）
- `HeartBeat`：ServiceName, LastBeatUtc, Detail

**label_group_id：** 有 Pallet → `OrderID|PalletID`；无 → `OrderID|NOPALLET|BatchID`（V3.8 起后者禁止进校准）。

**更新纪律：** 永远不改已写入的 raw/final/offset/stage*；V3.8 只许回填 lab_* / status / error。

## 第四部分：版本递进（后续怎么串）

| 版本 | 增量 | 最终多出来的效果 |

## 第六部分：任务拆解与责任边界（V3.7 执行序）

1. DDL 建库
2. 导出并修正 V3.7 推理入口
3. FeatureBuilder + PredictService + NSSM 脚本
4. MooneyWebServer（Controller+DAL+Swagger）
5. mooney_web_client 两页一健康页 + 代理
6. 本机联调按 §2.4
7. 生产：IIS 发前端+API，NSSM 发预测，按 §1.4 验收

**非目标（V3.7）：** 置信度运算、Lab 匹配、Power BI、FastAPI、改 MixingCurve 代码、写回 MMS。

## 第七部分：风险与现场知悉

1. 部署机必须能访问 MMS；V3.8 再确认 Datamart
2. IIS 需 Hosting Bundle，否则 ASP.NET 站点 500
3. 应用池回收不影响 NSSM 预测，但 API 短暂不可用——前端轮询应容忍失败重试
4. Pallet 空不挡 V3.7 展示，只影响 V3.8 校准资格
