## 1. 本版目标

- 详情顶卡：分数、HIGH/MED/LOW、区间、原因码（诊断模式可看六维）
- 列表置信度列；新页 `/mooney-kpi`
- **不删** V3.7 漏斗/特征；Trust **只 UPDATE** confidence/interval/reason 列

---

## 2. 本版方法

### 2.1 写库顺序（锁死）

```text
V3.7 INSERT（冻结 stage/raw/offset/final/experts）
  → TrustEngine.compute（读 features + 可选 state/lab）
  → UPDATE 仅 trust 相关列
禁止改 raw/final
```

六维规则与区间：总规格 §6.7；权重 `trust_weights.json`。

### 2.2 本版 API 调度

| 谁 | 何时 | 调什么 |
|----|------|--------|
| PredictService | 每车写库成功后 | 进程内调 TrustEngine（非前端） |
| KpiAggregator | 每日 1 次 | 写 `kpi_daily` |
| Vue 详情 | 进页 | 仍 `GET .../MooneyBatches/{o}/{b}`，读 **`.trust`**（V3.7 键已预留 null） |
| Vue 列表 | 5s Recent | `confidenceScore` / `confidenceLabel` |
| Vue KPI 页 | 进页 | `GET /api/Kpi/Summary?days=7` + `GET /api/Kpi/Daily?...` |

无新「推理 HTTP」；仍只有 ASP.NET 读库。

## 3. 执行步骤

| # | 动作 | 验收 |
|---|------|------|
| 0 | 前置检查 | — |
| 1 | ALTER trust 列 + `kpi_daily` | 表结构 OK |
| 2 | TrustEngine 单测 | 无 Lab 维 null 仍出分 |
| 3 | 接入 Predict | 新行有 score 或失败时 NULL 不挡 final |
| 4 | 可选历史回填 | — |
| 5 | API `.trust` + Kpi | Swagger |
| 6 | 前端顶卡 + 列表 | 绑定 `.trust.*` |
| 7 | KpiAggregator + `/mooney-kpi` | 小样本提示「样本不足」 |
| 8 | 验收 §7.3.4 | 含回归 V3.7/V3.8 |

---

## 4. 验收要点

1. 有专家 ≥1 reason；无则友好空态  
2. `interval_low ≤ final ≤ interval_high`  
3. Network 仍无 Python  
4. 旧 API 字段兼容  

重训 Activate 门禁：总规格 §7.3.5（**禁止**未人工确认自动 Activate）。
